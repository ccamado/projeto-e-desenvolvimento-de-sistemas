Git: como um projeto guarda sua história?

CEPEF · 3º A · Projeto e Desenvolvimento de Sistemas · 05/11/2026 · 6º tempo (11h20–12h10) · Professor Claudio Amado

1. Situação-problema — 5 minutos

A equipe da Central de Avisos criou vários arquivos: central_final.py, central_final2.py, central_final_agora.py. Qual é a versão correta? Se foi introduzido um erro, como descobrir quando ele apareceu?

Uma cópia isolada não documenta claramente qual mudança ocorreu, quem a registrou e como recuperar o estado anterior.

2. Conceitos — 8 minutos

Controle de versão: prática de acompanhar alterações feitas em arquivos de um projeto ao longo do tempo. Git: sistema de controle de versões. Repositório Git: arquivos e informações de histórico versionadas. GitHub: serviço de hospedagem e colaboração para repositórios Git; não é o próprio Git.

O objetivo de PDS é compreender e documentar a evolução do projeto, não memorizar comandos avançados.

3. Commit e mensagem — 8 minutos

ESTADO ANTERIOR

DER com título e descrição

ALTERAÇÃO

Adicionar atributo data

COMMIT

Registrar a alteração

ESTADO NOVO

DER atualizado

Uma mensagem "alterei o arquivo" é pouco informativa. Melhor: "Adiciona atributo data ao DER de Aviso". O commit é um registro no histórico, e não apenas apertar Salvar no editor.

4. Histórico fictício da Central — 9 minutos

v0.1Define requisitos da CentralEscopo inicial

Os números e mensagens são exemplos para análise em papel, não commits efetivamente feitos pela turma.

5. Simulação em duplas — 10 minutos

Recebam três alterações fictícias: A — criar README com orientações; B — incluir data no DER; C — corrigir requisito de listagem. Escolham uma ordem plausível e escrevam uma mensagem de commit clara para cada alteração. Justifiquem sua ordem.

Não há ordem única se não foi informada uma dependência entre as mudanças. Avalie a coerência e a justificativa.

6. Verificação individual — 7 minutos

  1. Por que duplicar arquivos com nome “final” não substitui um histórico?
  2. Defina repositório e commit.
  3. Por que a mensagem “mudei coisas” é inadequada?
  4. Qual versão fictícia documentou o DER?
  5. Git e GitHub significam a mesma coisa?

7. Resumo para o caderno — 3 minutos

Git é uma ferramenta de controle de versões. Repositório organiza arquivos e histórico. Commit registra mudanças. Mensagem de commit deve indicar o que foi alterado. Histórico ajuda a acompanhar versões anteriores. A Central de Avisos pode versionar requisitos, DER, código e documentação.
