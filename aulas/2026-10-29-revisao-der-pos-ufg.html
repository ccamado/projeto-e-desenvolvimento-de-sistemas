1. Revisão de DER — 3º A

  • Material de apoio apenas se houver tempo após a Avaliação UFG.
  • Revisão dos conteúdos já trabalhados de modelagem de dados.

2. Do problema ao modelo

  • Sistema: Central de Avisos.
  • Precisamos guardar informações úteis sobre avisos.
  • Modelar é representar os dados antes da implementação.

3. Entidade e atributo

  • Entidade AVISO: algo relevante sobre o qual guardamos dados.
  • Atributos possíveis: id, título, descrição, data, tipo.
  • Identificador distingue registros, mesmo com títulos repetidos.

4. Relacionamento

  • Relacionamento representa associação entre entidades.
  • Não criar outra entidade sem requisito que a justifique.
  • Exemplo condicionado: CATEGORIA associada a AVISO.

5. Cardinalidade

  • 1:N pode representar uma categoria com vários avisos.
  • Cada aviso pertence a uma categoria nesse cenário hipotético.
  • A regra de negócio determina a cardinalidade, não o desenho bonito.

6. Leitura de um modelo simples

  • AVISO(id, titulo, data, tipo)
  • Pergunta: qual campo identifica unicamente?
  • Que atributo é necessário para exibir o título?
  • Há entidade extra realmente necessária?

7. Atividade de consolidação

  • Desenhe AVISO e quatro atributos.
  • Proponha relação apenas se houver justificativa.
  • Explique por escrito uma cardinalidade escolhida.

8. Resumo para o caderno

  • Entidade: elemento relevante para armazenar dados.
  • Atributo: informação que descreve a entidade.
  • Relacionamento: associação entre entidades.
  • Cardinalidade: quantidade possível de associações.
  • DER representa conceitualmente os dados do sistema.
